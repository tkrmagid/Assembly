# Short Answer

### **Q1.** Provide examples of three different instruction mnemonics.

**정답:**
MOV, ADD, CALL (others: SUB, MUL, INC, DEC, JMP, RET, PUSH, POP, NOP)

> **해설:**
> 니모닉은 명령이 수행하는 연산의 이름을 나타내는 짧은 예약어다. 예: MOV(데이터 이동), ADD(덧셈), CALL(프로시저 호출).

---

### **Q2.** What is a calling convention, and how is it used in assembly language declarations?

**정답:**
The agreed way procedures receive parameters and clean up the stack; it is declared with .MODEL (e.g. flat,stdcall) and applies to PROTO/INVOKE declarations

> **해설:**
> 예를 들어 STDCALL은 인수를 오른쪽에서 왼쪽으로 푸시하고 호출된 프로시저가 스택에서 제거한다. .MODEL에 지정한 규약이 PROTO와 INVOKE의 기본값이 되어 어셈블러가 올바른 호출 시퀀스를 생성한다.

---

### **Q3.** How do you reserve space for the stack in a program?

**정답:**
.STACK directive, e.g. .stack 4096

> **해설:**
> .STACK 지시어(예: .stack 4096)로 런타임 스택 바이트 수를 어셈블러에 알려 준다.

---

### **Q4.** Explain why the term assembler language is not quite correct.

**정답:**
The assembler is the program that translates the source; the language itself is called assembly language

> **해설:**
> "assembly language"는 언어 이름이고 "assembler"는 번역 프로그램 이름이므로 "assembler language"는 둘을 혼동한 표현이다.

---

### **Q5.** Explain the difference between big endian and little endian. Also, look up the origins of this term on the Web.

**정답:**
Little endian stores the least significant byte at the lowest address (x86); big endian stores the most significant byte first. The term comes from Gulliver's Travels (which end of an egg to break)

> **해설:**
> 12345678h를 리틀 엔디언은 낮은 주소부터 78 56 34 12로, 빅 엔디언은 12 34 56 78로 저장한다. 이름은 스위프트의 걸리버 여행기에서 릴리퍼트 사람들이 삶은 달걀의 어느 쪽을 깰지 다툰 이야기에서 따왔다.

---

### **Q6.** Why might you use a symbolic constant rather than an integer literal in your code?

**정답:**
A name makes the code easier to read and lets you change the value in one place

> **해설:**
> COUNT = 500 같은 상수는 숫자의 의미를 설명해 주고 한 곳에서만 수정하면 된다. 어셈블러가 값을 치환하므로 실행 시 비용은 어느 쪽이든 같다.

---

### **Q7.** How is a source file different from a listing file?

**정답:**
The source file is what you write; the listing file is generated by the assembler and shows the source together with machine code, offsets and a symbol table

> **해설:**
> 리스팅(.lst) 파일은 어셈블의 부산물로, 각 소스 줄에 대해 어셈블러가 생성한 기계어를 확인할 수 있게 해 준다.

---

### **Q8.** How are data labels and code labels different?

**정답:**
A data label names a variable in a data segment (no colon); a code label marks an instruction address in the code segment and ends with a colon

> **해설:**
> 데이터 레이블(count DWORD 100)은 저장 위치를 나타내고, 코드 레이블(L1:)은 점프/루프 대상이다.

---

### **Q9.** (True/False): An identifier cannot begin with a numeric digit.

**정답:**
True

> **해설:**
> 식별자는 숫자를 포함할 수 있지만 문자, 밑줄, @, ?, $로 시작해야 한다.

---

### **Q10.** (True/False): A hexadecimal literal may be written as 0x3A.

**정답:**
False

> **해설:**
> MASM은 h 접미사를 쓴다: 3Ah. 16진 리터럴은 숫자로 시작해야 하며(0FFh), C 스타일 0x 접두사는 MASM에서 유효하지 않다.

---

### **Q11.** (True/False): Assembly language directives execute at runtime.

**정답:**
False

> **해설:**
> 지시어는 어셈블 시점에 어셈블러가 처리한다(데이터, 세그먼트, 프로시저 정의). 실행 시간에 실행되는 것은 명령어뿐이다.

---

### **Q12.** (True/False): Assembly language directives can be written in any combination of uppercase and lowercase letters.

**정답:**
True

> **해설:**
> 지시어는 대소문자를 구분하지 않는다: .data, .DATA, .Data는 모두 같다.

---

### **Q13.** Name the four basic parts of an assembly language instruction.

**정답:**
label, mnemonic, operand(s), comment

> **해설:**
> 명령문은 [레이블:] 니모닉 [피연산자] [; 주석] 형태다. 니모닉만 필수이고 레이블, 피연산자, 주석은 명령에 따라 선택적이다. (답의 순서는 상관없다.)

---

### **Q14.** (True/False): MOV is an example of an instruction mnemonic.

**정답:**
True

> **해설:**
> MOV는 데이터 이동 명령의 니모닉(기억을 돕는 약어)이다.

---

### **Q15.** (True/False): A code label is followed by a colon (:), but a data label does not end with a colon.

**정답:**
True

> **해설:**
> 예: L1:은 코드 레이블이고, count DWORD 100은 콜론 없는 데이터 레이블 count를 쓴다.

---

### **Q16.** Show an example of a block comment.

**정답:**
```asm
COMMENT !
This line is a comment.
This line is also a comment.
!
```

> **해설:**
> COMMENT 지시어는 구분 문자(여기서는 !)를 받으며, 그 문자가 다시 나타날 때까지의 내용을 어셈블러가 무시한다.

---

### **Q17.** Why is it not a good idea to use numeric addresses when writing instructions that access variables?

**정답:**
Variable offsets change whenever data is added, removed or reordered; labels are recalculated automatically by the assembler while hard-coded numbers silently become wrong

> **해설:**
> 레이블은 프로그램을 읽기 쉽게도 해 준다. 숫자만으로는 거기에 무엇이 저장되어 있는지 알 수 없다.

---

### **Q18.** What type of argument must be passed to the ExitProcess procedure?

**정답:**
a 32-bit integer (DWORD) — the process return code

> **해설:**
> 프로토타입이 ExitProcess PROTO,dwExitCode:DWORD이므로 호출은 INVOKE ExitProcess,0 형태다. 이 값이 프로그램의 반환 코드가 된다.

---

### **Q19.** Which directive ends a procedure?

**정답:**
ENDP

> **해설:**
> 프로시저는 이름 PROC로 시작해 이름 ENDP로 끝난다.

---

### **Q20.** In 32-bit mode, what is the purpose of the identifier in the END directive?

**정답:**
It names the program's entry point — the procedure where execution begins

> **해설:**
> END main은 소스 파일의 끝을 표시하고, 어셈블러/링커에 실행이 main에서 시작함을 알려 준다.

---

### **Q21.** What is the purpose of the PROTO directive?

**정답:**
To declare a prototype (name and parameter list) for an existing procedure so the assembler can check calls to it

> **해설:**
> 예: ExitProcess PROTO,dwExitCode:DWORD를 선언하면 INVOKE ExitProcess,0이 올바르게 검사되고 어셈블된다.

---

### **Q22.** (True/False): An Object file is produced by the Linker.

**정답:**
False

> **해설:**
> 오브젝트 파일은 어셈블러가 만들고, 링커는 오브젝트 파일과 라이브러리를 합쳐 실행 파일을 만든다.

---

### **Q23.** (True/False): A Listing file is produced by the Assembler.

**정답:**
True

> **해설:**
> 어셈블러는 선택적으로 소스 줄과 기계어를 함께 보여 주는 리스팅 파일을 생성할 수 있다.

---

### **Q24.** (True/False): A link library is added to a program just before producing an Executable file.

**정답:**
True

> **해설:**
> 링커가 오브젝트 파일과 링크 라이브러리(예: Irvine32.lib, kernel32.lib)를 합쳐 실행 파일을 만든다.

---

### **Q25.** Which data directive creates a 32-bit signed integer variable?

**정답:**
SDWORD

> **해설:**
> SDWORD = 부호 있는 더블워드(32비트, −2,147,483,648 … 2,147,483,647).

---

### **Q26.** Which data directive creates a 16-bit signed integer variable?

**정답:**
SWORD

> **해설:**
> SWORD = 부호 있는 워드(16비트, −32,768 … 32,767).

---

### **Q27.** Which data directive creates a 64-bit unsigned integer variable?

**정답:**
QWORD

> **해설:**
> QWORD = 쿼드워드(64비트, 8바이트).

---

### **Q28.** Which data directive creates an 8-bit signed integer variable?

**정답:**
SBYTE

> **해설:**
> SBYTE = 부호 있는 바이트(−128 … 127).

---

### **Q29.** Which data directive creates a 10-byte packed BCD variable?

**정답:**
TBYTE

> **해설:**
> TBYTE(10바이트)는 80비트 패킹 BCD 값을 정의하며 FPU의 FBLD/FBSTP와 함께 쓰인다.
