# Algorithm Workbench

### **Q1.** Define four symbolic constants that represent integer 25 in decimal, binary, octal, and hexadecimal formats.

**정답:**
```asm
COUNT_D = 25
COUNT_B = 11001b
COUNT_O = 31o
COUNT_H = 19h
```

> **해설:**
> 25 = 16+8+1 = 11001b = 8진 31(3·8+1) = 19h(1·16+9). 진법 접미사: b, o(또는 q), h; 10진은 접미사가 필요 없다.

---

### **Q2.** Find out, by trial and error, if a program can have multiple code and data segments.

**정답:**
Yes — .data and .code may each appear several times; the assembler merges them into their segments

> **해설:**
> .data와 .code 블록을 번갈아 둔 파일도 어셈블된다. 각 지시어는 현재 세그먼트를 전환할 뿐이고, 조각들은 하나로 합쳐진다.

### **Q3.** Create a data definition for a doubleword that stored it in memory in big endian format.

**정답:**
```asm
; value 12345678h stored big-endian (most significant byte first)
bigVal BYTE 12h,34h,56h,78h
```

> **해설:**
> DWORD로 정의하면 리틀 엔디언(78 56 34 12)으로 저장되므로, 최상위 바이트부터 바이트 단위로 직접 정의한다.

### **Q4.** Find out if you can declare a variable of type DWORD and assign it a negative value. What does this tell you about the assembler's type checking?

**정답:**
Yes, e.g. val DWORD -1 assembles (stored as FFFFFFFFh); the assembler does not enforce signed/unsigned type checking on initializers

> **해설:**
> 어셈블러는 2의 보수 비트 패턴을 그대로 저장할 뿐이다. 부호 여부는 나중에 명령어가 비트를 어떻게 해석하느냐의 문제다.

### **Q5.** Write a program that contains two instructions: (1) add the number 5 to the EAX register, and (2) add 5 to the EDX register. Generate a listing file and examine the machine code generated by the assembler. What differences, if any, did you find between the two instructions?

**정답:**
```asm
add eax,5      ; 83 C0 05
add edx,5      ; 83 C2 05
```

Only the second byte differs: C0 vs C2. The register field of the ModR/M byte encodes EAX (000) or EDX (010); the opcode 83 and the immediate 05 are identical.

> **해설:**
> 둘 다 같은 명령 형식(ADD r/m32, imm8)이다. 목적지 레지스터는 ModR/M 바이트의 3비트에 인코딩되며, 바뀌는 것은 그 부분뿐이다.

### **Q6.** Given the number 456789ABh, list out its byte values in little-endian order.

**정답:**
AB 89 67 45

> **해설:**
> 리틀 엔디언은 최하위 바이트를 먼저 저장한다: 가장 낮은 주소에 AB, 이어서 89, 67, 마지막에 45.

### **Q7.** Declare an array of 120 uninitialized unsigned doubleword values.

**정답:**
```asm
myArray DWORD 120 DUP(?)
```

> **해설:**
> DUP은 초기값을 반복하고 ?는 초기화하지 않음을 뜻한다. DWORD는 부호 없는 32비트 타입이다.

---

### **Q8.** Declare an array of byte and initialize it to the first 5 letters of the alphabet.

**정답:**
```asm
letters BYTE 'A','B','C','D','E'
; or equivalently:
letters BYTE "ABCDE"
```

> **해설:**
> 문자 리터럴은 ASCII 코드(41h…45h)로 저장된다. BYTE 정의에서의 문자열 리터럴은 문자 목록의 축약 표기일 뿐이다.

### **Q9.** Declare a 32-bit signed integer variable and initialize it with the smallest possible negative decimal value. (Hint: Refer to integer ranges in Chapter 1.)

**정답:**
```asm
minVal SDWORD -2147483648      ; -2^31 (80000000h)
```

> **해설:**
> 부호 있는 32비트 정수의 범위는 −2^31 = −2,147,483,648부터 2^31−1 = 2,147,483,647까지다.

### **Q10.** Declare an unsigned 16-bit integer variable named wArray that uses three initializers.

**정답:**
```asm
wArray WORD 10,20,30
```

> **해설:**
> WORD는 부호 없는 16비트 타입이고, 쉼표로 구분한 여러 초기값은 연속된 원소를 만든다.

### **Q11.** Declare a string variable containing the name of your favorite color. Initialize it as a null-terminated string.

**정답:**
```asm
favColor BYTE "blue",0
```

> **해설:**
> 널 종료 문자열은 0 바이트로 끝나서 WriteString 같은 라이브러리 프로시저가 끝을 알 수 있다.

---

### **Q12.** Declare an uninitialized array of 50 signed doublewords named dArray.

**정답:**
```asm
dArray SDWORD 50 DUP(?)
```

> **해설:**
> SDWORD는 부호 있는 32비트 타입이고, 50 DUP(?)는 초기화되지 않은 원소 50개(200바이트)를 예약한다.

---

### **Q13.** Declare a string variable containing the word "TEST" repeated 500 times.

**정답:**
```asm
testStr BYTE 500 DUP("TEST")      ; 2000 bytes
```

> **해설:**
> DUP은 문자열 초기값도 반복할 수 있으므로 500 DUP("TEST")는 TESTTEST…(2000바이트)를 만든다.

---

### **Q14.** Declare an array of 20 unsigned bytes named bArray and initialize all elements to zero.

**정답:**
```asm
bArray BYTE 20 DUP(0)
```

> **해설:**
> 20 DUP(0)은 각각 0으로 초기화된 바이트 20개를 만든다.

---

### **Q15.** Show the order of individual bytes in memory (lowest to highest) for the following doubleword variable:

```asm
val1 DWORD 87654321h
```

**정답:**
21 43 65 87

> **해설:**
> 리틀 엔디언: 최하위 바이트(21)가 오프셋 0, 이어서 43, 65, 최상위 바이트 87이 오프셋 3에 온다.
